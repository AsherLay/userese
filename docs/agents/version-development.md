# Userese 版本开发协议

当任务涉及实现、调整或关闭一个 Userese 版本时读取本文件。

## 读取顺序

1. `README.md` 与 `CONTEXT.md`
2. 当前版本 `spec/vX.Y/`
3. 对应 `design/versions/vX.Y/`
4. 与需求直接相关的 `SKILL.md`、`references/`、`scripts/` 和 `tests/`
5. 已接受且与本次决定相关的 `docs/adr/`

不要预读全部脚本、测试、历史版本或运行记录。先用需求 ID 确定修改面，再打开对应实现。

## 开发过程

1. 把需求拆成可独立验证的实现切片，并为每个切片标出需求 ID。
2. 先保留当前已发布行为的回归证据，再新增失败测试或验收夹具。
3. 优先使用确定性提取和结构化产物；模型只处理需要语义判断的内容。
4. 需求变化先更新 `spec/`；交互表达变化同步更新 `design/versions/`；长期决定进入 ADR。
5. 实现后运行 Skill 校验、单元测试和版本验收场景，记录未覆盖的框架、状态和数据源。

## 版本边界

- 规格状态为“准备实现”只授权本地实现，不授权外部模型费用、提交、推送、发布或生产动作。
- `VERSION` 在功能、文档和验收同时完成后才更新。
- 正式版本关闭前，`SKILL.md`、协议、脚本、测试、规格和设计不能互相矛盾。

完成标准：每条纳入范围的需求都有实现位置和验收证据；未完成项明确保留在版本状态中，不以接近完成代替发布完成。
